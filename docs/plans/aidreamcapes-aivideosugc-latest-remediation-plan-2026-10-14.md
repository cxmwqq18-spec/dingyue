# Aidreamcapes AIVideosUGC 最新整改与 P0 验收计划

- 日期：2026-10-14
- 状态：实施计划；本文不表示数据库已迁移、供应商已实测或功能已上线
- 适用范围：`site_aidreamcapes` 的私有 AIVideosUGC 工作台及其专用资产。AI 供应商维护界面只覆盖此前已批准的供应商配置改造。
- 当前基线：本地 `main-2` 工作区含有未提交的 AIVideosUGC 与供应商维护改造；本计划将“代码存在”“本地检查通过”“真实环境验收”“线上可用”分开记录。

## 1. 依据与当前决策

本计划综合以下资料：

- `ugc.zip` 中的《前端设计说明》《后端设计说明》：工作台流程、角色与分镜生成、任务版本、成片与字幕的目标设计。
- `移交技术-AIVideosUGC-20261013.zip` 中的技术说明、当前状态、待补功能清单及 D-001 至 D-012 决策记录：阶段范围和交接状态。
- 当前代码及此前本地核对：工作台、53 张角色卡、供应商维护、渲染和 smoke 检查的实现情况。
- `docs/plans/aidreamcapes-speech-28-voice-match-clone-plan.md` 与 `docs/plans/aidreamcapes-voiceover-and-subtitles-plan.md`。

实施时按较新的明确要求处理冲突：

1. **角色卡与默认音色作为一组呈现。** 用户选中角色卡时即使用该卡绑定的音色，不新增独立音色库或强制用户再次选声。运行时仍需保存稳定的供应商 `voiceId`，供服务端调用和任务快照使用。
2. **53 份角色样音是已生成的试听资产，不等于成片已使用这些音色。** 当前视频能力声明不支持音频参考，角色卡试听 MP3 尚未接入视频请求，也不能证明视频口播使用了对应 `voiceId`。
3. **精确音色与口型同步必须一起验收。** 先验证 speech-2.8、视频供应商及口型链路的实际能力、计费和输出；若无可靠同步路径，不能把角色样音直接覆盖到正在说话的视频上，也不能宣称成片精确使用该音色。
4. **角色声纹克隆不属于已完成项。** 当前 3–6 秒 MP3 是预设音色 TTS 样音，不满足文档所列的克隆参考音频时长条件。未取得合格参考音频和单独批准前，不创建克隆任务。
5. **交接材料提到的线上状态是交接记录，不是本轮线上复核。** 交接文档记录截至 10 月 13 日 GitHub main 为 `34fc1802`，8 个页面使用三步布局；“首页卖家卡和三步第 3 卡换真实视频”仍待处理。此项需在重新盘点后单列，不计入工作台后端 P0 完成证明。

## 3. P0 整改顺序

### P0-0：固定工作区与变更边界

1. 以当前本地 `main-2` 为整合基线，逐项检查未提交改动及其来源，不用线上旧代码覆盖本地功能。
2. 核对所有数据库与资产写入仅针对 `site_aidreamcapes` 和当前客户；不对其他站点做跨站迁移或更新。
3. 保持 Aidreamcapes 隔离规则：不改 MyDreamShoots 数据、页面、导航、SEO、资产或共享默认值。发布前检查变更文件范围。
4. 不导入、恢复或回退历史发布快照。任务、角色及媒体以当前关系数据和显式字段更新为准。

**完成条件：** 变更清单可审阅；所有涉及站点的写入都含 `site_aidreamcapes` 限定；无快照恢复路径。

### P0-1：补齐数据库结构和真实持久化验收

1. 检查 `scripts/setup-aidreamcapes-workspace.mjs`、`src/lib/aidreamcapes-workspace/store.ts` 和生产数据库当前结构，明确 `AidreamcapesVideoTask`、`AidreamcapesWorkspaceActor` 的唯一建表来源。
2. 若缺少受版本控制的正式结构迁移，新增作用域明确、可重复执行的迁移并记录 schema；若生产环境已有表，则先对照列、索引、约束和触发器，避免重复建表或破坏数据。
3. 按项目发布流程应用迁移，随后以 `site_aidreamcapes` 测试客户验证创建、读取、更新、删除、revision 冲突、跨客户拒绝和站点隔离。
4. 验证素材记录与文件归属同一客户和任务，删除/失败时不会误删其他任务资产。

**完成条件：** 迁移记录、数据库结构核对、真实读写回读和所有权隔离结果齐全。

### P0-2：完成供应商配置落库与旧通道兼容验收

1. 在目标数据库应用供应商 runtime config 迁移，并核对协议、模型族、时长、画幅、原生语音等字段的读写和默认值。
2. 通过后台表单配置至少一个获准的文本、图像、视频及 ASR 通道；密钥仅保存在服务端，不回显给浏览器日志。
3. 分别核对新版协议适配和仍需保留的旧通道；验证启用/禁用、优先级、超时、错误回退、连接测试和任务状态。
4. 对视频供应商的可用时长按**单次供应商请求**配置。30 秒工作台输出当前拆成 2 个 15 秒调用，必须验证两次调用的成功/失败处理与总价。

**完成条件：** 数据库读回值与后台表单一致；新旧通道各有受控请求证据；失败回退不会产生重复提交或重复扣费。

### P0-3：把角色卡音色绑定落实到服务端任务快照

1. 将 `actor-voice-assets.json` 中经过锁定的供应商 voice ID 纳入服务端角色目录，使用稳定 actor ID 查找，不能按页面列表位置推导。
2. 选中角色卡时默认绑定其 voice ID；用户界面继续以角色卡为入口，不要求单独维护/选择音色。当前阶段不增加独立音色目录。
3. 在任务输入和镜头版本快照中保存角色 ID、实际 voice ID、语言、台词及音频模式，确保重试和历史版本不会悄悄切换声音。
4. 分清三种状态并在界面如实表达：角色卡试听样音、视频模型原生口播、speech-2.8 生成并经口型链路验收的精确音色。不能把第一种标为后两种。
5. 先人工听审 53 个样音并记录音色/语言/发音结果，修订不合格映射后冻结候选清单。

**完成条件：** 53 个 actor 与 voice ID 映射稳定、性别一致；任务和每个镜头均保存映射快照；样音听审结果可追溯。

### P0-4：用一个角色验证真实声音、口型与费用

1. 从已听审的角色中选一名，按角色卡 `sampleLine` 生成一段受控测试内容。
2. 验证 speech-2.8 的请求确实使用该卡绑定的 voice ID，音频文件有效，并记录请求 ID、实际时长、费用和输出资产归属。
3. 核实视频供应商是否支持音频参考/音频驱动口型。当前代码将 `audioReference` 标为 `false`，不能在没有能力证据时将其改成 `true`。
4. 若供应商不支持音频参考，先验证独立 lip-sync 服务；只有实际口型结果通过人工样片检查才可接通角色 TTS 成片。若两种方案都不可用，工作台继续明确标示“描述引导音色”，不承诺 exact voice。
5. 实际生成前核对 speech、视频、合成/lip-sync 各项费用和重试规则；采用明确限额的小样任务，不启用全量自动生成。

**完成条件：** 样片音轨使用指定 voice ID、口型达到验收标准、计费与素材归属可核对；否则把精确音色能力保持为不可用并记录阻塞项。

### P0-5：字幕与最终导出端到端验收

1. 配置 ASR 服务并确认可访问，检查字幕功能的可用状态与错误提示。
2. 对最终混音后的音轨生成时间戳，规范化核对识别文案与最终台词；不得用估算台词时间直接烧录成“已验证字幕”。
3. 验证多镜头时间偏移、SRT 下载、三种字幕样式、目标语言字体、安全边距和背景音乐混音。
4. 测试无音轨、ASR 超时、文本不匹配、FFmpeg 失败、重试及关闭字幕后的恢复路径。

**完成条件：** 成片、SRT 与音轨文案一致，字幕时间无明显漂移；故障状态可见且不会留下错误标记为成功的产物。

### P0-6：账务、幂等与用户验收

1. 核对视频积分计算：6/10/15 秒分别 24/40/60；30 秒两次 15 秒调用为 120。与平台真实扣费记录对账。
2. 验证报价、提交、轮询、重试、取消及并发操作；每个镜头版本只能结算一次，失败重试不得重复扣费。
3. 验证 3 个工作台场景、角色选择、素材上传、分镜编辑/锁定/重抽、单镜头生成、合片和历史任务恢复。
4. 验证客户只能访问自己的任务与素材，接口拒绝跨站和跨客户 ID；供应商密钥不出现在页面、响应或日志。
5. 形成逐项验收表，标注“通过/不通过/未配置”，并附供应商请求记录、数据库回读、扣费回读和样片检查结果。

**完成条件：** 私有工作台从新建任务到下载成片的真实路径通过；未通过项保持关闭或明确标注，不以 smoke 结果替代。
