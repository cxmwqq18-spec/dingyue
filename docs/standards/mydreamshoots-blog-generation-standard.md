# MyDreamShoots 博客生成规范

本规范用于 MyDreamShoots `.com` 的博客选题、写作、审核、预览和后续维护。它描述的是建议的内容生产流程，不代表系统已经把所有步骤自动化。附件截图只用于确认现有博客模块、导航和视频主题分类，不作为公开文案、事实来源或内部提示语的复制来源。

## 适用范围

- 公开内容使用英文，面向 MyDreamShoots `.com` 读者。
- 文章使用现有 `blog_article` 内容类型和 `blog_detail_1` 区块，不新增前台组件或文章类型。
- 产品事实、SEO 文案、主题链接和图片必须来自当前本地内容库、主题页或已经核实的本地素材。
- 价格、积分、时长、模型能力等可能变化的信息不写死；文章应链接到当前主题页，让主题页承担实时产品信息。
- 不把生成内容描述成真实事件、身份验证、产品证明、官方背书或未经授权的人物发言。
- 本地草稿和本地预览可以同步用于读回；生产发布、部署和其他站点内容不属于本规范的默认操作。

## 从选题到上线的 13 步流程

| 步骤 | 具体操作 | 完成时应得到什么 |
| --- | --- | --- |
| **1. 明确写作任务** | 写清楚目标读者、遇到的问题、读完应该知道什么或能做什么；确认语言、网站和产品范围。 | 一份简短写作要求 |
| **2. 确定选题与搜索意图** | 选择一个核心问题，整理相关问题；判断读者需要教程、解释、对比还是选购建议。 | 主问题与相关问题清单 |
| **3. 检查已有内容** | 查看网站是否已有相同主题，判断应更新、扩展还是新建，并明确新文章的边界。 | 新写或更新的决定 |
| **4. 收集并核实资料** | 查询可靠来源，核对产品实际功能与限制；记录数字、案例、引述的出处，不确定的内容标记待核实。 | 可引用的资料与事实清单 |
| **5. 确定文章角度** | 用一句话说明文章的核心答案，明确比泛泛介绍多提供什么，例如真实操作、决策标准或失败处理。 | 核心结论与文章切入点 |
| **6. 编写大纲** | 为每个章节写出“回答什么问题、需要什么证据”；按读者理解和操作顺序排列。 | 标题、章节及各节要点 |
| **7. 按章节写初稿** | 可以先写主体，再写开头和结尾。每节先给答案，再解释原因，最后补充例子或操作方法。 | 一篇完整初稿 |
| **8. 补充实用内容** | 教程补前置条件、步骤和结果；对比补统一标准与适用人群；建议补限制和不适用情况。 | 读者可以实际使用的内容 |
| **9. 编辑与润色** | 删除套话、重复和无依据的夸张表述，统一术语，拆分过长段落，检查前后逻辑。 | 清楚、连贯的正文 |
| **10. 配图与内链** | 按内容需要配图，检查图片能否准确说明正文；自然链接到相关产品或文章，避免无关导流。 | 图文完整的文章 |
| **11. 完善 SEO 信息** | 确保标题与正文一致，填写准确摘要和简洁 URL，整理标题层级与图片替代文本，避免关键词堆砌。 | 完整的页面信息 |
| **12. 发布前审核与上线读回** | 检查事实、错字、图片、链接和产品承诺；删除内部说明。上线或写入本地预览后，查看真实页面，确认内容完整、展示正常。 | 可以交付给读者的线上或预览文章 |
| **13. 根据反馈更新** | 根据读者反馈、搜索表现和产品变化，补充遗漏、修正过时内容；复查事实、内链、canonical 和图片。 | 持续维护的文章 |

## 三个强制检查点

1. **大纲是否答对问题**：每个主要章节都应回答读者的一个相关问题，并且有事实、步骤或判断标准支撑。
2. **正文是否有事实支撑**：功能、限制、适用条件、产品 CTA 和权限提醒必须能追溯到当前主题页或已核实资料；不确定的信息不能写成确定承诺。
3. **真实页面是否呈现最终内容**：写入本地预览后要读回博客首页、文章新地址和旧地址重定向，确认 canonical、目录、图片、内链和移动端展示没有回退。

## 文章交付门禁

每篇文章至少应包含：

- 一个明确的搜索意图和开头直接答案；
- 5–8 个主题章节，至少 4 个 H2；
- 产品适用场景、前置条件、限制，以及与相邻主题的比较；
- 4–6 个 FAQ，至少 3 个 FAQ H3；
- 可扫描的列表、表格或检查清单；
- 产品主题页 CTA 和 3–5 条有效的相关内链；
- SEO title、description、keywords、canonical 路径和图片替代文本；
- 约 3,400 个字符以上的正文，且不能依靠重复句子凑长度；
- 英文公开文案，不含中文内部说明、提示词、测试占位符或编辑备注；
- 不含模板化夸张承诺，例如“ultimate solution”“game changer”“effortlessly”或暗示结果必然稳定、真实、官方或准确的表述。

## 版本、路由和数据边界

- 主题更名或 URL 迁移时，使用新的主题一致 canonical；旧 URL 使用永久重定向，不在 sitemap、canonical、BlogPosting 或博客列表中继续作为新页面。
- 若一个旧别名可能属于多个视频主题，按最接近的主题迁移，避免所有旧链接落到同一篇文章。
- 本地内容同步只允许作用于指定的 MyDreamShoots 文章 slug；确认数据库是本地且可恢复后，才可以同步 draft 和 preview publication。
- 不修改 AidreamShoots 西语文章，不把共享路由兼容逻辑扩展成其他站点的内容迁移。
- 封面优先复用现有本地素材；不同文章的封面必须唯一，图片实际存在，并且能说明文章主题。

## 发布后维护

产品主题页、权限要求、导航路径、SEO 描述或素材发生变化时，应重新执行资料核实、事实审查、链接检查和真实页面读回。若反馈显示读者仍未解决核心问题，优先更新相关章节和 FAQ，而不是只改标题或堆叠关键词。
